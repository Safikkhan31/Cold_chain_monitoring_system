# AWS infrastructure (Terraform)

```
Internet
  |-- :80   --> frontend EC2 (public subnet)  --:3000--> backend EC2 (private subnet) --:5432--> RDS PostgreSQL (isolated DB subnets)
  |-- :1883 --> ingest EC2: Mosquitto + mqtt-ingest (public subnet) ------------------:5432--> RDS
  |-- :8080 (your IP only) --> Jenkins (public subnet): runs the pipeline and the Docker builds itself

Git push -> Jenkins (polls Git) -> builds images -> ECR -> AWS SSM runs /opt/coldchain/deploy.sh on each server -> server pulls the new image
```

## What gets created
| Area | Resources |
|---|---|
| Network | VPC, 2 public + 2 private + 2 database subnets over 2 AZs, internet gateway, one NAT gateway, 3 route tables (the DB one has no internet route), S3 gateway endpoint, DB network ACL, VPC flow logs to CloudWatch, locked-down default security group, private DNS zone (`backend.coldchain.internal`) |
| Security groups | One per role. The backend only accepts port 3000 from the frontend. RDS only accepts 5432 from backend, ingest and Jenkins. Jenkins UI only from `admin_cidrs`. Outbound is limited to HTTPS (plus 5432 and 3000 where needed) |
| ECR | 3 repositories (backend, frontend, mqtt-ingest) with scan on push, encryption and keep-last-10 cleanup |
| Compute | EC2 for backend, frontend, ingest; Jenkins. IMDSv2 only, encrypted disks, no SSH keys or open SSH ports (use SSM Session Manager) |
| Data | RDS PostgreSQL 16, encrypted, private, password generated by AWS and kept in Secrets Manager; MQTT passwords in Secrets Manager |
| IAM | App servers can pull only their own image and read only their own secrets. Jenkins can push to the 3 repos, run the deploy script on exactly those 3 servers, and read the DB secret, and nothing else |

## Deploy
```bash
cd terraform
cp terraform.tfvars.example terraform.tfvars    # set admin_cidrs to your IP, e.g. ["203.0.113.10/32"]
terraform init
terraform plan
terraform apply
```
Wait about 10 minutes (RDS is slow), then `terraform output`.

## One-time Jenkins setup
1. Get the unlock password through Session Manager (no SSH needed):
   `aws ssm start-session --target $(terraform output -raw jenkins_instance_id)`, then `sudo cat /var/lib/jenkins/secrets/initialAdminPassword`.
2. Open `terraform output jenkins_url`, unlock, install the suggested plugins, and create your admin user.
3. Manage Jenkins > Nodes > Built-In Node > Configure: set *Number of executors* to 1 (saves memory on a small server).
4. Create a job: New Item > Pipeline > *Pipeline script from SCM* > Git > your repo URL (add credentials if it is private) > script path `Jenkinsfile`.
5. Run it once. After that, Jenkins checks Git every 2 minutes and deploys new commits.

There is no separate build agent. Builds run on the Jenkins server, so the free-tier vCPU limit (8) is not exceeded.

The repo you give Jenkins must contain the project root (`Jenkinsfile`, `backend/`, `frontend/`, `mqtt-ingest/`, `database/`). The `terraform/` folder can live in the same repo.

## After the first successful pipeline run
- Dashboard: `terraform output dashboard_url`.
- ESP32 firmware: `MQTT_HOST` = `terraform output -raw mqtt_host`, `MQTT_USER` = `esp32`, `MQTT_PASS` = `terraform output -raw mqtt_esp32_password`.
- Servers are first created with no image, so their first deploy fails harmlessly until the pipeline pushes one.

## Webhook instead of polling (optional)
Set `webhook_cidrs` to GitHub's hook IP ranges (https://api.github.com/meta), add a webhook to `http://<jenkins-ip>:8080/github-webhook/`, install the GitHub plugin, and remove `pollSCM` from the `Jenkinsfile`.

## Known limits and hardening for real production use
- Jenkins and the dashboard use plain HTTP, and MQTT is unencrypted on 1883. Add an ALB with an ACM certificate for the dashboard and Jenkins, and TLS (8883) for MQTT.
- Single NAT gateway, single-AZ RDS and one server per role. Use one NAT per AZ, `multi_az = true` and an autoscaling group for availability.
- The apps connect to RDS as the master user, and the connection skips certificate verification (`sslmode=no-verify`, still encrypted). Create a limited app user and add the RDS CA bundle.
- Builds and the Jenkins controller share one server. Anyone who can create or edit jobs can use Docker (root-equivalent) and Jenkins' AWS permissions, so keep Jenkins admin to yourself, keep `admin_cidrs` tight, and only build repos you trust. A separate agent, as in the earlier version, isolates this.
- The Jenkins server is not backed up. Snapshot `/var/lib/jenkins` or use AWS Backup.
- Terraform state holds generated secrets. Use the encrypted S3 backend shown in `versions.tf`.
- Rollback: re-run the pipeline on an older commit. Images are kept as tags per commit (last 10).
- Cost and free tier: defaults are t3.micro servers, db.t4g.micro and RDS backups off, so the apply works on free-tier accounts. The free tier covers about 750 instance-hours a month in total, and this setup runs five servers. The NAT gateway, public IPv4 addresses, Secrets Manager and flow logs are not free either. On the newer free plan the difference comes out of your credits. Stop the instances when you are not using them, and run `terraform destroy` when you are done.
- t3.micro has 1 GB of RAM. The bootstrap adds a 2 GB swap file so Jenkins and Docker builds do not run out of memory, but expect slow builds.
